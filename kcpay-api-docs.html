1. What is KC Pay?

KC Pay is a payment gateway built for Zambia that allows you to accept payments via:

  • Mobile Money — MTN, Airtel, and Zamtel
  • Card Payments — Visa, Mastercard (via hosted payment page)

All transactions are processed in ZMW (Zambian Kwacha). The API is simple — just 2 endpoints to integrate: one to initiate payments and one to check status. KC Pay also sends webhooks to your server when payments complete.

Why KC Pay? Simple REST API. No complex SDKs. Works with any language (Node.js, PHP, Python, etc.). Supports mobile money and cards. Built for Zambian businesses.

2. Getting Started — Create Your Account

Before you can integrate KC Pay, you need a merchant account. Follow these steps:

1

Create a KC Pay Account

Visit https://kundananjicreations.com/pages/member_login and register for a new account. You will need to provide your business details.

2

Create a Product

Once logged in, navigate to your dashboard and create a Product. This represents what you are selling (e.g., "My SaaS Subscription", "Event Tickets", "Online Store"). You will receive a Product Reference — save this, you'll need it for API calls.

3

Get Your API Credentials

From your KC Pay dashboard, locate your:

  • API Username
  • API Password
  • Product Reference (from the product you created)
  • Public Key and Private Key (if you plan to accept card payments)
4

Set Up Your Callback URL

In your KC Pay dashboard, configure your Callback URL (webhook). This is the URL on your server where KC Pay will send payment results. For example:

https://yourdomain.com/api/payments/callback

This URL must be publicly accessible — KC Pay's servers need to reach it directly.

5

Store Credentials Securely

Add your credentials to your project's environment variables (e.g., a .env file). Never hard-code credentials in your source code.

# .env file
KCPAY_BASE_URL=https://productcheckout.kundananjicreations.com/
KCPAY_USERNAME=your_api_username
KCPAY_PASSWORD=your_api_password
KCPAY_PRODUCT_REFERENCE=YourProductName
KCPAY_PUBLIC_KEY=pk_live_xxxx
KCPAY_PRIVATE_KEY=sk_live_xxxx
KCPAY_MODE=test
⚠ Security Never commit your .env file to Git or any version control system. Add it to your .gitignore.

Here is a summary of the credentials you'll use throughout the integration:

Product Reference KC Pay Dashboard → Products Identifying what the customer is paying for
Public Key KC Pay Dashboard Card payments only
Private Key KC Pay Dashboard Card payments only

Authentication

KC Pay uses username + password authentication. Credentials are sent in the request body (not headers) with every API call:

{
  "apiUserName": "your_api_username",
  "apiPassword": "your_api_password"
}
ℹ Note There is no OAuth or token-based authentication. Your username and password authenticate each request directly.

4. How It Works — Payment Flow

Mobile Money Flow

1. Customer chooses to payYour app / website
→
2. Your server calls KC PayPOST to Initiate endpoint
→
3. USSD push sent to phoneCustomer approves on phone
→
4. KC Pay sends webhookPOST to your callback URL
→
5. You fulfill the orderActivate, deliver, etc.

Card Payment Flow

1. Customer chooses cardYour app / website
→
2. Your server calls KC PayPOST to Initiate endpoint
→
3. Redirect to KC Pay pageCustomer enters card details
→
4. KC Pay sends webhookPOST to your callback URL
→
5. You fulfill the orderActivate, deliver, etc.

Key Concepts

  • sellerReference — A unique ID you generate for each payment (e.g., ORD-1707123456-X7). Use this to match callbacks to your orders.
  • token — Returned by KC Pay after initiating a payment. Used for status checks and card payment redirects.
  • Callback / Webhook — KC Pay POSTs the payment result to your server. This is the primary way to know if a payment succeeded.
  • Polling — As a fallback, you can poll KC Pay's status endpoint to check if a payment has completed.

6. Step 2: Check Payment Status (Polling)

After initiating a payment, you can poll this endpoint to check if the customer has completed it. This is useful as a fallback in case the webhook doesn't arrive.

POST https://productcheckout.kundananjicreations.com/request-status

You can query by token, sellerReference, or transactionId:

By Token

{
  "apiUserName": "your_username",
  "apiPassword": "your_password",
  "token": "txn_abc123def456"
}

By Seller Reference

{
  "apiUserName": "your_username",
  "apiPassword": "your_password",
  "sellerReference": "ORD-1707123456-X7"
}

Response

{
  "status": "Success",
  "transactionId": "KC-789012",
  "paymentMethod": "mobilemoney",
  "amount": 50.00,
  "completedAt": "2026-02-16 12:30:00"
}

Possible Status Values

StatusMeaningWhat to Do
success / successfulPayment completedFulfill the order
pending / processingWaiting for customerKeep polling (every 5 seconds)
failedPayment failed or rejectedShow error, allow retry
⚠ Polling Best Practice Poll every 5 seconds for up to 2 minutes. If the response says "transaction not found," the transaction may still be propagating — treat it as pending and keep polling.

7. Step 3: Receive Payment Callback (Webhook)

When a payment completes (or fails), KC Pay sends a POST request to your callback URL. This is the most reliable way to know the payment result.

POST https://yourdomain.com/api/payments/callback
🔒 Important Your callback endpoint must be publicly accessible with no authentication. KC Pay's servers need to POST to it directly. Make sure your firewall, hosting, and CORS settings allow this.

Callback Payload (sent by KC Pay)

{
  "status": "Success",
  "sellerReference": "ORD-1707123456-X7",
  "transactionId": "KC-789012",
  "token": "txn_abc123def456",
  "amount": 50.00,
  "paymentMethod": "mobilemoney",
  "completedAt": "2026-02-16 12:30:00"
}

How to Process the Callback

  1. Parse the incoming JSON body
  2. Find the matching order/payment in your database using sellerReference
  3. Check the status field
  4. If "Success" or "Successful" → mark the order as paid, deliver the product/service
  5. If anything else → mark as failed, notify the customer
  6. Respond with HTTP 200 so KC Pay knows you received it

Your Server Should Respond

ScenarioHTTP CodeResponse
Processed successfully200{ "success": true }
Order not found404{ "success": false, "message": "Order not found" }
Server error500{ "success": false, "message": "Internal error" }

8. Card Payments (Redirect Flow)

For card payments, the flow is slightly different. After initiating the payment, you redirect the customer to KC Pay's hosted payment page where they enter their card details.

Step-by-Step

  1. Call the Initiate Payment endpoint with "paymentMethod": "card"
  2. KC Pay returns a token in the response
  3. Construct the payment URL and redirect the customer:
GET https://productcheckout.kundananjicreations.com/pay-for-product?transactionToken={token}
  1. The customer enters their card details on KC Pay's secure page
  2. KC Pay processes the payment and sends a callback to your webhook URL
  3. The customer is redirected back to your site

Example: Constructing the Redirect URL

Node.js 
const paymentUrl = `${KCPAY_BASE_URL}/pay-for-product?transactionToken=${token}`;
// Send this URL to your frontend, which redirects the user
res.json({ success: true, payment_url: paymentUrl });
PHP 
$paymentUrl = $baseUrl . '/pay-for-product?transactionToken=' . $token;
header('Location: ' . $paymentUrl);
exit;

9. Full Code Examples

Here are complete, copy-paste-ready examples for initiating a mobile money payment in popular languages.

Node.js (Express)

Install 
npm install express dotenv
server.js 
const express = require('express');
require('dotenv').config();
const app = express();
app.use(express.json());

const KCPAY_BASE_URL = process.env.KCPAY_BASE_URL;
const KCPAY_USERNAME = process.env.KCPAY_USERNAME;
const KCPAY_PASSWORD = process.env.KCPAY_PASSWORD;
const KCPAY_PRODUCT  = process.env.KCPAY_PRODUCT_REFERENCE;

// ── Initiate a payment ──
app.post('/api/pay', async (req, res) => {
  const { amount, phone, network, customerName, customerEmail } = req.body;

  // Generate a unique reference for this payment
  const reference = 'ORD-' + Date.now() + '-' + Math.random().toString(36).slice(2, 6).toUpperCase();

  // Strip leading 0 from phone number
  const cleanPhone = phone.replace(/^0/, '');

  try {
    const response = await fetch(KCPAY_BASE_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        apiUserName: KCPAY_USERNAME,
        apiPassword: KCPAY_PASSWORD,
        amount: parseFloat(amount),
        paymentMethod: 'mobilemoney',
        source: KCPAY_PRODUCT,
        country: 'zm',
        currency: 'ZMW',
        sellerReference: reference,
        products: [{ productReference: KCPAY_PRODUCT, quantity: 1, amount: parseFloat(amount) }],
        customerName: customerName || '',
        customerEmail: customerEmail || '',
        customerPhoneNumber: cleanPhone,
        network: network.toLowerCase(),
        accountNo: cleanPhone,
      }),
      signal: AbortSignal.timeout(30000),
    });

    const data = await response.json();

    if (data.status === 'Success') {
      // TODO: Save reference, token, and order details to your database
      res.json({ success: true, reference, token: data.token, message: 'Check your phone for the payment prompt' });
    } else {
      res.status(400).json({ success: false, message: data.message || 'Payment initiation failed' });
    }
  } catch (err) {
    console.error('KC Pay error:', err);
    res.status(500).json({ success: false, message: 'Payment gateway error' });
  }
});

// ── Check payment status ──
app.get('/api/pay/status/:reference', async (req, res) => {
  try {
    const response = await fetch(KCPAY_BASE_URL + 'request-status', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        apiUserName: KCPAY_USERNAME,
        apiPassword: KCPAY_PASSWORD,
        sellerReference: req.params.reference,
      }),
      signal: AbortSignal.timeout(30000),
    });

    const data = await response.json();
    const status = (data.status || '').toLowerCase();

    if (['success', 'successful'].includes(status)) {
      // TODO: Mark order as paid in your database
      res.json({ success: true, status: 'completed' });
    } else if (['pending', 'processing'].includes(status)) {
      res.json({ success: true, status: 'pending' });
    } else {
      res.json({ success: true, status: 'failed' });
    }
  } catch (err) {
    res.status(500).json({ success: false, message: 'Status check failed' });
  }
});

// ── Receive KC Pay callback (webhook) ──
app.post('/api/payments/callback', (req, res) => {
  const { status, sellerReference, transactionId, amount } = req.body;
  console.log('KC Pay callback:', { status, sellerReference, transactionId, amount });

  const paymentStatus = (status || '').toLowerCase();

  if (['success', 'successful'].includes(paymentStatus)) {
    // TODO: Find order by sellerReference and mark as paid
    console.log(`Payment ${sellerReference} completed!`);
  } else {
    // TODO: Mark order as failed
    console.log(`Payment ${sellerReference} failed: ${status}`);
  }

  res.json({ success: true });
});

app.listen(3000, () => console.log('Server running on port 3000'));

Python (Flask)

Install 
pip install flask requests python-dotenv
app.py 
import os, time, random, string, requests
from flask import Flask, request, jsonify
from dotenv import load_dotenv

load_dotenv()
app = Flask(__name__)

BASE_URL = os.getenv('KCPAY_BASE_URL')
USERNAME = os.getenv('KCPAY_USERNAME')
PASSWORD = os.getenv('KCPAY_PASSWORD')
PRODUCT  = os.getenv('KCPAY_PRODUCT_REFERENCE')

@app.route('/api/pay', methods=['POST'])
def initiate_payment():
    data = request.json
    phone = data['phone'].lstrip('0')
    ref = f"ORD-{int(time.time())}-{''.join(random.choices(string.ascii_uppercase, k=4))}"

    payload = {
        'apiUserName': USERNAME,
        'apiPassword': PASSWORD,
        'amount': float(data['amount']),
        'paymentMethod': 'mobilemoney',
        'source': PRODUCT,
        'country': 'zm',
        'currency': 'ZMW',
        'sellerReference': ref,
        'products': [{'productReference': PRODUCT, 'quantity': 1, 'amount': float(data['amount'])}],
        'customerPhoneNumber': phone,
        'network': data['network'].lower(),
        'accountNo': phone,
    }

    resp = requests.post(BASE_URL, json=payload, timeout=30)
    result = resp.json()

    if result.get('status') == 'Success':
        # TODO: Save ref and token to your database
        return jsonify(success=True, reference=ref, token=result.get('token'))
    return jsonify(success=False, message=result.get('message', 'Failed')), 400

@app.route('/api/payments/callback', methods=['POST'])
def callback():
    body = request.json
    status = (body.get('status') or '').lower()
    ref = body.get('sellerReference', '')

    if status in ('success', 'successful'):
        # TODO: Mark order as paid
        print(f'Payment {ref} completed!')
    else:
        print(f'Payment {ref} failed: {status}')

    return jsonify(success=True)

if __name__ == '__main__':
    app.run(port=3000)

10. Error Handling

Recommended Timeout

Set a 30-second timeout on all requests to KC Pay. If the gateway doesn't respond in time, fail gracefully and let the customer retry.

Common Errors & Solutions

ErrorCauseSolution
Invalid credentialsWrong API username or passwordDouble-check credentials in your .env / dashboard
Transaction not foundStatus check too early after initiationWait a few seconds and retry — the transaction may still be propagating
Request timeoutKC Pay server is slow or downRetry after a short delay; show a friendly error to the user
Callback not receivedFirewall blocking, incorrect URL, or server downEnsure your callback URL is publicly accessible; use polling as a fallback
Phone prompt not receivedWrong phone number or network mismatchVerify the phone number and network are correct; ensure leading 0 is stripped
Duplicate sellerReferenceSame reference used for two paymentsAlways generate a unique reference per transaction
ℹ Best Practice Always implement both the webhook callback and status polling. The webhook is faster and more reliable, but polling ensures you don't miss a payment if the webhook fails to deliver.

Troubleshooting Checklist

  1. ✅ API credentials are correct (check KC Pay dashboard)
  2. ✅ Base URL ends with / — https://productcheckout.kundananjicreations.com/
  3. ✅ Phone numbers have no leading 0
  4. ✅ network is lowercase: "mtn", "airtel", or "zamtel"
